# Архитектурная идея: Приватное S3 хранилище (SeaweedFS + Nginx X-Accel-Redirect)

## 📌 Суть концепции

Использовать **Nginx** не просто как прокси, а как «умный контроллер отдачи данных».
Тяжелые бинарные файлы (картинки, документы, бэкапы) **НЕ** гоняются через RabbitMQ, Redis или код HTTP-моста. Архитектура проверяет права пользователя через быстрые JSON-запросы, а саму отдачу байтов перекладывает на Nginx.

---

## 🔄 Схема работы запроса

1. **User** шлет запрос: `GET /api/files/avatar_123.jpg`.
2. **Nginx** проксирует его на **HTTP-мост**.
3. **HTTP-мост** проверяет права юзера (быстро через **Redis** или коротким `true/false` RPC-запросом в **RabbitMQ**).
4. **Результат проверки**:
   * **Нет прав:** Мост сразу возвращает клиенту `403 Forbidden`.
   * **Есть права:** Мост возвращает **пустой ответ** с заголовком:
     `X-Accel-Redirect: /internal-s3/user-content/avatar_123.jpg`
5. **Nginx** перехватывает этот заголовок, понимает, что доступ одобрен, идет во внутреннюю сеть Docker, сам забирает файл из **SeaweedFS** и стримит его пользователю.

---

## 🛡️ Безопасность инфраструктуры

* У **SeaweedFS** нет открытых портов наружу (секция `ports` в Docker Compose отсутствует). Он полностью изолирован в приватной сети `s3-network`.
* Доступ к эндпоинту `/internal-s3/` из интернета намертво заблокирован директивой `internal;` в Nginx. Вызвать его напрямую извне невозможно (вернет 404).
* Ключи доступа к S3 генерируются через `openssl rand -hex` и безопасно прокидываются в контейнеры через `docker secrets` без хардкода в переменных окружения.

## 📂 Файлы конфигурации

### 1. `docker-compose.yml`

```yaml
version: '3.8'

networks:
  s3-network:
    driver: bridge

secrets:
  s3_access_key:
    file: ./s3_access_key.txt
  s3_secret_key:
    file: ./s3_secret_key.txt

services:
  nginx:
    image: nginx:alpine
    container_name: nginx-proxy
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    networks:
      - s3-network
    restart: always

  http-bridge:
    image: your-bridge-image:latest
    container_name: http-bridge
    networks:
      - s3-network

  seaweedfs:
    image: chrislusf/seaweedfs:latest
    container_name: seaweedfs
    networks:
      - s3-network
    volumes:
      - seaweed_data:/data
    secrets:
      - s3_access_key
      - s3_secret_key
    environment:
      - SEAWEEDFS_S3_ACCESS_KEY_FILE=/run/secrets/s3_access_key
      - SEAWEEDFS_S3_SECRET_KEY_FILE=/run/secrets/s3_secret_key
    command: 'server -dir=/data -s3 -s3.config=env'
    restart: always

volumes:
  seaweed_data:
```

### 2. `nginx.conf`

```nginx
events {}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;
    client_max_body_size 100M; 

    server {
        listen 80;
        server_name your-domain.com;

        # Публичная точка входа для клиентов
        location /api/ {
            proxy_pass http://http-bridge:3000/;
            proxy_set_header Host \$host;
            proxy_set_header X-Real-IP \$remote_addr;
        }

        # Секретный внутренний путь для сборки файлов из S3
        location /internal-s3/ {
            internal; # Полная изоляция от внешнего мира

            # Отрезаем префикс перед отправкой в SeaweedFS
            rewrite ^/internal-s3/(.*) /\$1 break;

            proxy_pass http://seaweedfs:8333; # Внутренний порт S3 API
            proxy_set_header Host \$host;
            proxy_set_header Authorization ""; # Защита от утечки заголовков авторизации
        }
    }
}
```

### 3. Пример ответа от HTTP-моста (при успешной авторизации)

```http
HTTP/1.1 200 OK
X-Accel-Redirect: /internal-s3/имя_бакета/путь_к_файлу.png
Content-Length: 0
Connection: keep-alive
```

## 🚀 Профит для архитектуры

1. **Zero-load на шину:** Исключены OOM-ошибки и тормоза RabbitMQ/Redis из-за прокачки тяжелой бинарщины.
2. **Абсолютный контроль прав:** Логика проверки прав остается гибкой (микросервисной), но данные отдает максимально производительный C-движок (Nginx).
3. **Независимость от вендоров:** SeaweedFS полностью бесплатен, обновляется еженедельно, нет лицензионных ограничений на объем данных и количество ядер, в отличие от современного MinIO.
